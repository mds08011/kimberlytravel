Planning Stripe Sequences with Yardage and Carry Analysis

July 2026

Stripe Plan turns an ordered stripe sequence — this color for so many rows, repeated so many times — into the four things a striped project actually needs decided up front: a to-scale preview of the fabric, a merged row schedule, per-color yardage apportioned from the pattern's total, and a verdict per color on whether it can be carried up the edge or has to be cut. Single file, offline, multiple named plans in localStorage [1].

The problem

Stripes look like the easy colorwork, and then three specific things go wrong. The proportions that looked right as a list of numbers look wrong as fabric — six rows of a dark color reads far heavier than six rows of a light one, and nobody wants to discover that eight inches in. The yarn runs out unevenly — stripes consume each color at different rates, and the pattern's single total-yardage number says nothing about how much of it is the contrast. And the edge becomes a decision fatigue generator: at every color change, carry or cut? Answering all three before casting on is arithmetic, which is what this tool is.

How it works

Build one repeat of the sequence as a list of stripes — a palette color and a row count each, reorderable, up to 40 stripes and 12 colors. Set the repeat count, your row gauge, and optionally the pattern's total yardage. Everything below updates live: a facts line (rows per repeat, total rows, finished length at gauge), the fabric preview drawn to scale with dashed lines at repeat boundaries, the per-color table, and the row schedule. Plans are named projects like the row counter's [2]; every change saves instantly.

The math

Merging and the schedule

The sequence is expanded across its repeats and adjacent same-color stripes are merged — including across the repeat boundary, the case hand-written schedules get wrong. A sequence ending in 3 rows of A whose next repeat begins with 4 rows of A is one 7-row stripe, and the schedule says so:

Rows 1–4: A
Rows 5–6: MC
Rows 7–13: A     ← 3 + 4 merged across the boundary

The Copy schedule button emits the full merged schedule with a palette key — and each "Rows n–m" boundary is exactly what to pin as a change-row note in Row & Repeat [2].

Yardage apportionment

Per-color yardage is the pattern's total split by each color's share of the rows, using largest-remainder rounding so the per-color figures sum exactly to the total. No invented yards-per-stitch constants — the accuracy is inherited from the pattern's own number, which is stated honestly in the tool's footer.

color_yd = round-by-largest-remainder( total_yd × color_rows / total_rows )

Carry or cut

For each color, the tool finds every block of rows where it is in use and measures the gaps between them. If the longest gap is at most 6 rows, the color can be carried up the edge; longer than that and each oversized gap is a cut — the table reports carry up (max gap 6) or cut ×3 (max gap 8), so the total ends-to-weave count is known before the first cast-on.

Editing the config

The constants at the top of the <script> block: CARRY_MAX (6 rows — houses differ; some carry up to 8, some catch mid-way and carry forever), MAX_COLORS (12), MAX_TOTAL_ROWS (2,000, the sanity cap on repeats × rows), and DEFAULT_PALETTE. Plans live under stripeplan.v1.

Limitations

  • Yardage is proportional to rows, which assumes every row consumes similar yarn — true for a constant-width piece, off for heavily shaped ones. For a shaped garment, apportion the pattern's per-size total and treat the split as an estimate.
  • The carry rule is a straight row-gap threshold. It does not know about jogless-join techniques, steeks, or working flat vs. in the round — the verdict is where to start, not the last word.
  • One sequence per plan. Compound layouts (a hem sequence, then a body sequence) are two plans.
  • Plans are per-device (localStorage); the copied schedule is the portable form.

Update: temperature blankets & computed yardage (v2.0.0)

Version 2.0.0 adds a second mode and reworks the yarn estimate. A mode toggle at the top switches between the stripe sequence above and a temperature blanket planner; the palette is now a list of named colors, each with optional ball-band grams and length that can be pulled read-only from the Skein & Gauge stash [2].

Temperature blanket mode

A year of daily temperatures is pasted in — one number per line, or CSV with a numeric column — because the offline rule forbids a weather API. The parser finds the numeric column and skips headers and malformed rows (a strict bare-number test keeps a 2026-01-01 date from being read as the number 2026), reporting how many days parsed and how many lines it skipped. Ordered bins map temperature ranges to colors; each bin colors temps up to its cutoff and the last bin catches everything above. A distribution readout shows days-per-bin before you commit — so a bin holding 120 of 365 days, which is a lot of one color to buy, is visible while it can still be rebalanced. Boundaries are inclusive-low: a 40.0° reading lands in the 40–49 bin, not the <40 one. Any day that falls outside every bin is listed in a warning rather than silently dropped.

Computed yardage (supersedes the apportionment above)

The v1 model apportioned a pattern's stated total by row share. Since a temperature blanket has no such total, v2 estimates yards-per-row from the fabric instead, and both modes now use it:

yards_per_row = stitches × (basis ÷ stitch_gauge) × fabric_factor ÷ 36
skeins        = ceil(yards × 1.10 ÷ ball_length)     (10% margin)

The fabric factor (default 3.0, the ratio of yarn-path length to stitch width for stockinette) is a visible, tunable field — garter and crochet run higher. It is an estimate, and one measured row beats any factor: a Measured yд/row override, when set, wins outright. Skeins appear per color wherever a ball length is set. The stripe mode also gains a Fibonacci fill (1, 1, 2, 3, 5, 8… widths cycling the palette) and a "repeat to N rows" control.

v2 limitations

  • Yards-per-row is an estimate governed by the fabric factor; measure one row and enter it to override the guess.
  • Temperature data is paste-in by design — the tool never goes online. Any weather source is copied in by hand.
  • A plan is one mode at a time; a project mixing a temperature body with a striped border is two plans.
